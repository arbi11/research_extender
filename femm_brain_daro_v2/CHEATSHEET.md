## Engine facts

- **python_route**: Scripts are ordinary Python 3 using femm-qt's pyFEMM: `sys.path.insert(0, "/opt/femm/share/femm/pyfemm")`, `from femm import *`, then `openfemm(1)` (1 = headless: it starts femm_headless from the FEMM_DIR folder, or attaches to a FEMM already serving port 48015) and `closefemm()` at the end. When pyFEMM connects, FEMM's working directory becomes the script's current directory, so relative paths resolve there; a later os.chdir does not move it, but `callfemm('setcurrentdirectory("dir")')` does. A second openfemm while connected raises "femm-qt is already connected to another client". For runs in parallel, give each its own `FemmSession(port=N, headless=True)` and call the commands as its methods. In the image the interpreter is /opt/venv/bin/python3 (3.12), without numpy. pyFEMM defines none of the Lua binding's constants (mm, inch, muo, Tesla, PI, I): use math.pi, 4e-7 * math.pi and 1j.
- **builtin_python**: FEMM can also run a script itself: `femm_headless -run script.py` executes it in FEMM's built-in Python (MicroPython), which is what chapter 3 of the manual describes. There the commands exist without any import or openfemm(), and several results come back as a tuple. pyFEMM's client-side shortcuts do not exist: mo_getb, mo_geth and mo_geta raise NameError, so use mo_getpointvalues.
- **errors_raise**: When FEMM rejects a command, pyFEMM raises `Exception("FEMM returns:\n<message>")`: catch it with try/except Exception. A wrong number of arguments is rejected the same way, except by pyFEMM's own functions with fixed parameters (newdocument, opendocument, mi_drawline, mi_drawarc, mi_drawrectangle, mi_setcurrent, mo_getb and the other two-coordinate mo_get functions), where Python raises TypeError, which except Exception also catches. An mo_ command before any solution is loaded fails with "name 'mo_...' isn't defined", and after mo_close with "No magnetics output in focus".
- **arguments**: pyFEMM sends each argument as text made with str(), so floats arrive at full precision and come back unchanged. Strings go inside double quotes with no escaping, so one that contains a double quote fails with "invalid syntax". None is sent as the word None and FEMM decides what it means: a required number such as a coordinate fails with "can't convert NoneType to float", while an optional argument (the editaction of a move or copy, the editmode of mi_selectrectangle and mi_selectcircle, the group of mo_groupselectblock) or a property value (mi_addmaterial, mi_addboundprop, mi_addpointprop, the circuit of mi_setblockprop) counts as left out, and the values after it still apply. mi_probdef is the exception: there a None ends the call, and it and every later argument keep their current values. "<None>" always works for no circuit or boundary.
- **results_shapes**: Several results come back as one list (`xmin, xmax, ymin, ymax = mi_getboundingbox()`; mo_getpointvalues gives a list of 14), one result as a bare number, and an empty reply as []: an empty document's mi_getboundingbox() is [], so unpacking it fails. A wrapper without a return gives None even when FEMM replies, for example mi_selectgroup.
- **text_results_garbled**: Before reading a reply, pyFEMM turns every i and I into 1j (to read complex numbers), so text that contains those letters comes back garbled: mi_gettitle() for /tmp/inside.fem returns '/tmp/1jns1jde.fem'. A reply that is not a number stays a string: infinity arrives as '1jnf' and not-a-number as 'nan'. Check that a result is a number before calculating with it.
- **angles**: FEMM's angle arguments are degrees: arc angles in mi_drawarc and mi_addarc, rotations, magnetisation directions and mo_getgapb angles. Python's math works in radians, so convert with math.radians and math.degrees.
- **complex_numbers**: AC (frequency > 0) results come back as Python complex numbers; DC results are plain int or float. Use z.real, z.imag, abs(z) and z.conjugate(). A complex argument works too: pyFEMM sends 3+4j as (3+4*I). In an AC circuit, volts = R I + j omega (flux linkage).
- **current_direction**: In a planar problem a positive circuit current flows out of the page (+z), so its field circulates counter-clockwise: 5 mm to the right of a +100 A wire, B points +y.
- **results_in_si**: Post-processor results are SI whatever the drawing unit: areas in m^2, volumes in m^3, B in T, H in A/m, current in A, force in N, torque in N m. In a planar problem, volumes, energies, forces, torques and flux linkage already include the depth set in mi_probdef. Exception: mo_getpointvalues gives conductivity in MS/m and current density in MA/m^2.
- **air_gap_band**: An air-gap boundary (format 6 periodic or 7 anti-periodic) goes on the two concentric arcs, inner and outer, that bound the gap. The band between them must carry a "<No Mesh>" block label: with no label the solver stops with "Solver returned error code 2560", and with an ordinary Air label it solves without any error but mo_getgapb gives half the right Bt. On a full 360-degree model use the periodic format 6: the anti-periodic format 7 forces the field to reverse round the circle, and here it gave Bt = 0. mo_getpointvalues returns [] inside the band (it has no mesh), so mo_getb and the other pyFEMM shortcuts fail there with IndexError; read the gap field with mo_getgapb.
- **prescribed_a_units**: A prescribed-A boundary sets A = A0 + A1 x + A2 y with x and y in drawing units. In a millimetre model, A1 = -0.001 on the outer boundary gives a uniform By of 1 T (By = -dA/dx).
- **torque_sign**: Torque results are positive counter-clockwise (+z). A magnet magnetised along +x in a uniform +y field gets a positive weighted-stress-tensor torque (mo_blockintegral type 22), as m x B predicts.
- **save_before_solve**: mi_analyze solves the saved file, so a new model must be saved with mi_saveas first. Analyzing an unsaved document raises an error. Save under a new name to keep an original .fem unchanged.
- **dxf_line_endings**: mi_readdxf can silently stop after the first entity, depending on the file's layout: group codes padded to three characters (" 0", the usual layout and mi_savedxf's own) come in whole only with CRLF line endings, and unpadded codes ("0") only with LF. A wrong pairing raises no error. mi_savedxf writes padded codes with LF, so FEMM cannot read its own DXF back unchanged. Check every import with mi_getboundingbox, and switch the line endings if it stopped early.
- **selection**: Selections add up until mi_clearselected (or mo_clearblock). mi_selectnode, mi_selectsegment, mi_selectarcsegment and mi_selectlabel toggle: selecting the same object twice deselects it. mi_selectgroup, mi_selectrectangle and mi_selectcircle only add and never deselect. In the post-processor, mo_selectblock and mo_groupselectblock both toggle. Every move, copy, scale or mirror clears the selection afterwards, so select again before each edit. The single selects return [] when there is nothing to select.
- **edits_reset_node_properties**: Every move, rotate, copy, scale or mirror (mi_movetranslate, mi_moverotate, mi_copytranslate, mi_copyrotate, mi_scale, mi_mirror), even with nothing selected, resets the point property and group of every node in the drawing to none and 0, including nodes it did not touch. Segments, arcs and block labels keep their properties and groups, and adding nodes, lines or labels resets nothing. So set point properties and node groups after the last move or copy, and do not rely on mi_selectgroup to find nodes after one.
- **material_library**: mi_getmaterial uses femm-qt's materials library, whose names differ from FEMM 4.2's: "M-19 Steel", "NdFeB 40 MGOe", "Pure Iron" and "1010 Steel" fail with "Couldn't load", and names are case-sensitive. Names that load include magnets "N30" to "N55", "SmCo24", "Ceramic 8A"; steels "M-19 14 mil" to "M-47 18 mil" (laminated), "M-19", "M-27", "Pure iron, annealed", "1010 Steel (hot rolled)"; "Air", "Copper", "Aluminum, 6061-T6" and wire such as "18 AWG". The full list is under mi_getmaterial. Library data may not match a paper (N42 is linear, N48 and N52 carry B-H curves): check before relying on it.

## Where this engine differs from the manual or FEMM 4.2

- `hidepointprops`: FEMM 4.2 used it to hide its floating point-properties window, which femm-qt does not have. pyFEMM defines it as pass and sends nothing, so it works even with no FEMM connected. [binding] [tested]
- `mi_addarc`: maxseg is degrees per piece, not the number of pieces the manual describes, and mi_addarc keeps it as given: 90 meshed each 180-degree arc as 2 chords. Only mi_setarcsegmentprop caps it at 10. [tested]
- `mi_createmesh`: The manual says it returns the number of elements; FEMM sends nothing, and pyFEMM's wrapper returns None anyway. Count elements after a solve with mo_numelements(). [manual] [binding] [tested]
- `mi_drawarc`: maxseg is degrees per piece, not a number of pieces as the manual suggests, and it is kept as given: a circle of two 180-degree arcs meshed as a 72-gon with maxseg 5 and as a square with maxseg 90. [tested]
- `mi_getmaterial`: The library is femm-qt's, not FEMM 4.2's: the 4.2 names "M-19 Steel", "M-27 Steel", "M-36 Steel", "Pure Iron", "1010 Steel", "NdFeB 32 MGOe", "NdFeB 40 MGOe", "Alnico 5", "Ceramic 8", "SmCo 24 MGOe" and "Hiperco-50" all fail, as do "M-400-50A", "35JN270" and odd gauges such as "19 AWG". [tested]
- `mi_movetranslate`: Without editaction it moves every selected type and ignores mi_seteditmode, although the manual says the edit mode applies. [tested]
- `mi_selectarcsegment`: The manual gives no return value; FEMM sends the end points and pyFEMM passes them on. [tested]
- `mi_selectgroup`: The manual says it first clears the selection; the engine adds to it and never deselects, so call mi_clearselected first. [tested]
- `mi_selectsegment`: The manual gives no return value; FEMM sends the end points and pyFEMM passes them on. [tested]
- `mi_setarcsegmentprop`: The manual gives no cap, and mi_drawarc and mi_addarc keep any maxseg they are given: a circle of radius 10 mm drawn with maxseg 90 meshed as a square (200 mm^2). Only this command caps it. [tested]
- `mi_seteditmode`: Contrary to the manual, the move, copy, scale and mirror commands do not use it: without an editaction they act on every selected type (mi_movetranslate in blocks mode moved a selected node). [tested]
- `mo_getallnodes`: Through pyFEMM it was about three times as fast as the loop here (0.1 s against 0.3 s), well short of the manual's 50 times: pyFEMM evaluates each value on its own. [tested]
- `mo_getfill`: The manual calls ff the fill factor for laminated materials, but this engine gave -1 for solid copper, air and a laminated block (lamination fill 0.9), and the copper fraction of a magnet-wire winding: 20 turns of 0.5 mm wire in a 4 x 4 mm block gave 0.2454 = 20 pi 0.25^2 / 16. [tested]
- `mo_lineintegral`: In a static problem type 3 returns only the two DC force values, though the manual lists four; at 50 Hz it returns four, the 2x pair complex. Type 4 gives [torque, 0] when static. [tested]
- `newdocument`: The manual's other name, create(doctype), has no pyFEMM function; callfemm('create(0)') reaches it and opened a magnetics document. mi_newdocument() instead resets the document in focus. [manual] [tested]
- `showpointprops`: FEMM 4.2 used it to show its floating point-properties window, which femm-qt does not have. pyFEMM defines it as pass and sends nothing, so it works even with no FEMM connected. [binding] [tested]

## Failures that raise no error

- `callfemm_noeval`: When FEMM closes the connection it returns quietly instead of raising, which is why closefemm uses it to send quit() (see quit). [binding]
- `mi_addbhpoint`: With a curve the solver ignores mu_x and mu_y: Iron with mu 1000 and the straight curve B = 500 mu0 H solved at mu_r 500. The nonlinear solve needs nothing else. [tested]
- `mi_addbhpoints`: Both forms work: B = 500 mu0 H given as [b, h] pairs solved at mu_r 500, and B = 250 mu0 H given as two lists at mu_r 250 (the material's mu_x 1000 ignored). Tuples work as pairs too. [tested]
- `mi_addbhpoints`: With two lists, zip() pairs them and silently drops the extra values of the longer one: 3 B and 2 H values stored 2 points. A flat list of numbers raises TypeError. [tested]
- `mi_addblocklabel`: A label placed on a segment is silently not added, with no error. [tested]
- `mi_addcircprop`: Leaving out circuittype (or passing None) silently gives a parallel circuit: two equal wires on mi_addcircprop("D", 10) got 5 A each. Leaving out i gives 0 A. Always pass all three. [tested]
- `mi_addmaterial`: A material stays linear until it gets B-H points (mi_addbhpoint, mi_addbhpoints); then mu_x and mu_y are ignored. [tested]
- `mi_addnode`: A node at the position of a block label is silently not added, with no error. [tested]
- `mi_addsegment`: It creates no nodes: each end snaps to the nearest existing node however far away it is, so a missing node silently gives a segment to the wrong node. [tested]
- `mi_addsegment`: When both ends snap to the same node (for example only one node exists) nothing is added and no error is raised. [tested]
- `mi_clearbhpoints`: An unknown name is ignored without an error. [tested]
- `mi_close`: With nothing in focus it raises no error, and the solution of a closed input stays open: mo_gettitle() still worked after it. [tested]
- `mi_deleteboundprop`: An unknown name is ignored without an error. [tested]
- `mi_deletecircuit`: Blocks that were in it then carry no current, and the solve raises no error: the fixture wire solved with 0 A and no field, and mo_getcircuitproperties then raised "Unknown circuit Iw". [tested]
- `mi_deletecircuit`: An unknown name is ignored without an error. [tested]
- `mi_deletematerial`: An unknown name is ignored without an error. [tested]
- `mi_deletepointprop`: Nodes that used it lose it without an error: a 100 A point current vanished from the solution. [tested]
- `mi_deletepointprop`: An unknown name is ignored without an error. [tested]
- `mi_modifyboundprop`: propnum 0 renames the boundary, but segments and arcs keep the old name and so silently lose the condition: after renaming A0 the arcs had none and B was 0. Reassign them after a rename. [tested]
- `mi_modifyboundprop`: An unknown name is ignored without an error. [tested]
- `mi_modifycircprop`: propnum 0 renames the circuit, but block labels keep the old name and silently drop out of it: after renaming C to D the wires carried 0 A while D still reported 4 A. [tested]
- `mi_modifycircprop`: An unknown name is ignored without an error. [tested]
- `mi_modifymaterial`: An unknown name or propnum (99) is ignored without an error. [tested]
- `mi_modifypointprop`: propnum 0 renames it, but nodes keep the old name and silently lose it: after renaming, the field was 0. [tested]
- `mi_modifypointprop`: An unknown name is ignored without an error. [tested]
- `mi_newdocument`: It resets the open document in place (geometry, materials, boundaries and problem definition; the title becomes Untitled.fem, which pyFEMM garbles to 'Unt1jtled.fem') instead of opening a second one. Use newdocument(0) for a new document. [tested]
- `mi_probdef`: Arguments left off keep their current values instead of being reset. A new document starts at 0 Hz, millimeters, planar, precision 1e-8, depth 1, min angle 30, acsolver 0. [tested]
- `mi_probdef`: A None silently ends the list: it and every argument after it keep their current values, so mi_probdef(0, "millimeters", "planar", None, 7) left the depth unchanged. (mi_addmaterial, by contrast, skips only the None position.) [tested]
- `mi_probdef`: Out-of-range values give no error: precision 1e-5 is stored as 1e-8, and min angle 40 or acsolver 3 leave the previous value. [tested]
- `mi_readdxf`: Whether a file comes in whole depends on its layout: group codes padded to three characters (as mi_savedxf writes them) need CRLF line endings, unpadded codes need LF. The wrong pairing stops after the first entity with no error (see fact:dxf_line_endings), so check the result with mi_getboundingbox. [tested]
- `mi_savebitmap`: A path in a folder that does not exist writes nothing and raises no error; no argument raises a wrong-count error. [tested]
- `mi_savemetafile`: No file is written and no error is raised; FEMM even accepts it with no argument. [tested]
- `mi_setcurrent`: It is exactly mi_modifycircprop(name, 1, i): the saved .fem was identical, and the circuit stayed series. It takes exactly two arguments (a TypeError otherwise), and an unknown name is ignored without an error. [tested]
- `mi_seteditmode`: An unknown name is ignored without an error and the mode stays as it was. [tested]
- `mi_setfocus`: A name that matches nothing raises no error and leaves the focus where it was; check with mi_gettitle(). [tested]
- `mi_setgrid`: The type is document state, saved as [Coordinates]. In polar a prescribed-A boundary means A0 + A1 r + A2 theta instead of A0 + A1 x + A2 y: A1 = -0.001 on a circle gave B = 0 instead of 1 T. Set "cart" again before solving such a model. [tested]
- `mi_setprevious`: With prevtype 1 or 2 the solver reuses the mesh stored in the .ans: a model re-meshed finer solved on the old 7890 elements instead of its own 32976. Keep the geometry unchanged; a frozen solve of the same linear model reproduced the original field. [tested]
- `mo_bendcontour`: An angle outside -180 to 180 (270 here) is ignored without an error: the piece stays straight. [tested]
- `mo_blockintegral`: An unknown type (31) returns 0 without an error. [tested]
- `mo_clearcontour`: mo_lineintegral on an empty contour returns [0, 0] instead of raising an error, so a missing contour fails silently; mo_makeplot does raise ("No contour defined for makeplot"). [tested]
- `mo_gapintegral`: A misspelt boundary name returns 0 without an error, so it looks like a zero result. [tested]
- `mo_getallgapa`: npts 0 gives one value, as npts 1 does (A at 0 degrees); a misspelt boundary name gives [] without an error. [tested]
- `mo_getallgapb`: A misspelt boundary name gives [] without an error. [tested]
- `mo_getallgapharmonics`: It takes the name only: a second argument raises "takes 1 positional arguments but 2 were given". A misspelt name gives [] without an error. [tested]
- `mo_getelement`: Element and node indices are 1-based; index 0, -1 or N + 1 returns [] without an error, so unpacking it fails. A non-integer index raises "can't convert non-integer float to int". [tested]
- `mo_getgapa`: A misspelt boundary name returns 0 without an error. [tested]
- `mo_getgapb`: The band between two circles needs the air-gap boundary on both circles (all four arcs here) and a <No Mesh> label inside it: with no label the solve raises "Solver returned error code 2560", and with an Air label it solves without an error but Bt comes out half the right value. [tested]
- `mo_getgapb`: A misspelt boundary name returns [0, 0] without an error. [tested]
- `mo_getnode`: Indices are 1-based and match those mo_getelement returns. mo_getnode(0) and mo_getnode(N + 1) return [] without an error. [tested]
- `mo_getpointvalues`: A point with no mesh (outside the model, or inside a <No Mesh> region such as the air-gap band) returns [] and raises no error, so unpacking or indexing it fails. In the band use mo_getgapb. [tested]
- `mo_groupselectblock`: Like mo_selectblock it toggles: calling it twice for the same group leaves nothing selected. A group with no blocks selects nothing, without an error. [tested]
- `mo_lineintegral`: An unknown type (6) returns [] without an error. [tested]
- `mo_makeplot`: NumPoints 1 gives 2 points (the two ends); an unknown PlotType (9) writes zeros under the header "Position, Value" without an error; an unwritable path raises "Could not open output file". [tested]
- `mo_selectblock`: A point outside the mesh (outside the model, or in a <No Mesh> region) selects nothing, without an error; mo_blockintegral then raises 'No area selected for integration'. [tested]
- `mo_seteditmode`: An unknown mode string is accepted without an error. [tested]
- `mo_setfocus`: A name that matches nothing raises no error and keeps the focus; check with mo_gettitle(). [tested]
- `mo_setweightingscheme`: Values outside 0 to 4 (5, -1) are accepted without an error. [tested]
- `newdocument`: An out-of-range type (4) raised no error, so check the number. [tested]
- `opendocument`: Opening a .ans raises no error but loads nothing: no input or output got the focus. To read a saved solution, open its .fem and call mi_loadsolution(). [tested]
